# Проверка Kodex с настоящим Codex

Дата: 23 сентября 2026. Codex CLI и общий app-server daemon: **0.156.1**.
Среда: Qt 6.11.2, KDE Frameworks 6.30.0, Breeze, C++23.

Проверки ниже выполнялись через установленный `codex`, существующую авторизацию
аккаунта и реальный app-server. Интерактивные проверки загружают тот же QML и
C++ backend, используют Qt mouse/key/input events, а не подменяют ответы модели.
Отдельно запускался собранный `build/kodex`, который открывал реальную сессию.
Обычные регрессионные тесты с fake server дополняют эти проверки.

## Исправления, найденные проверками

- Новая задача используется из ответа `thread/start`: до первого хода у неё
  ещё нет rollout, поэтому немедленный `thread/resume` был ошибкой.
- Архив читается через `thread/read`; продолжение разрешается после unarchive.
- Прерванные команды получают статус «Остановлено», включая историю.
  Добавлен регрессионный тест для безопасного обращения со значением JSON статуса.
- При явном отключении сбрасываются ожидающие RPC callbacks; поздние ответы
  не вызывают уже закрытые компоненты.
- Готовый план имеет явный выбор реализации; сама выдача плана не запускает код.
- Кнопки ответов закреплены под прокручиваемой формой. Длинные варианты
  переносятся, стандартные RadioButton не перекрывают подписи.
- Меню модели/effort/доступа привязаны к компактным селекторам и открываются вверх.
- Чат сохраняет конец ответа при изменении размера и появлении панели плана.
- В подтверждении сразу видны точная команда и рабочий каталог.
- Diff подсвечивается; в узком окне блок Git-действий сворачивается,
  освобождая место для патча. Кнопки composer остаются внутри панели.

## Независимое визуальное ревью

Отдельный агент проверял снимки и исходники без редактирования файлов.
Замечания проверялись повторно после исправлений. Финальное заключение:
все найденные P1/P2 устранены; в проверенных светлой/тёмной темах и при
850×600 дополнительных исправлений не требуется. Артефакты сохраняются
в `build/live-artifacts/`:

- `01-questions*.png`, `02-questions-answered.png` — реальные вопросы;
- `03-plan-ready.png`, `04-implemented.png` — решение о реализации и результат;
- `05-running*.png`, `06-stopped.png` — выполняемая и остановленная задача;
- `07-model-menu.png`, `08-compact-window.png` — меню и компактное окно;
- `10-approval-decline.png`, `11-approval-accept.png` — подтверждения;
- `12-compacted.png`, `13-archived-task.png`, `14-restored-task.png` — история;
- `15-diff-light.png`, `16-diff-dark.png`, `17-diff-compact*.png` — настоящий патч
  с добавлением и удалением строк в обеих KDE-темах.

KDE-палитры загружаются до QApplication из отдельных временных `kdeglobals`.
Тест дополнительно проверяет фактическую яркость изображения. Изменение
`QApplication::setPalette` внутри одного процесса для этой проверки не используется.

## Повторный запуск

```sh
cmake --build build
ctest --test-dir build --output-on-failure

KODEX_LIVE_WORKFLOW=1 ./build/kodex_live_tests
QT_QPA_PLATFORMTHEME=kde KODEX_LIVE_INTERACTIVE=1 ./build/kodex_interactive_tests
./scripts/test-native-ui.sh
```

Можно запускать отдельные сценарии: `taskSwitching`, `realInteractiveScenarios`,
`approvalsCompactionAndArchive`, `visualDiffThemes`. Live-тесты расходуют лимиты
аккаунта. Они создают собственные временные проекты/задачи и удаляют их после
проверки; пользовательские репозитории и общий daemon не перезапускаются.

## Что не проверялось вручную

Новый вход/выход через браузер, физическое сопряжение телефона и обновление
рабочей установки Codex не выполнялись. Использовалась существующая авторизация;
состояние remote-control читалось с настоящего сервера. Pairing и updater имеют
отдельные автоматические проверки с имитацией сервера/установщика. Внешний push
проверялся только на локальном bare remote, без отправки на GitHub.
